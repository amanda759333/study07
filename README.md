# 팀 편성 웹 앱 (중간 과제)

학생이 스스로 팀을 편성하는 Streamlit 앱. 마감 뒤 남은 학생은 AI(오픈라우터 무료 모델)가 배정하고, 앱이 그 배정안을 규칙으로 검사한다.
아래 1~7항은 공고 7.1절 양식을 따른다.

## 1. 배포 주소

**(배포 후 채움)** — Streamlit Community Cloud, 브랜치 `master`, 앱 파일 `streamlit_app.py`

## 2. PRD와 구현 계획의 위치

- PRD: [docs/PRD.md](docs/PRD.md) — 등장인물, 2.3 팀 규칙, 2.4 지원과 투표, 2.5 마감과 배정을 요구사항으로 정리하고 출처 절을 표시
- 구현 계획: [docs/구현 계획.md](docs/구현%20계획.md) — 화면·DB 테이블·모듈 단위, 교수님 작업 순서(A~E단계, #1~#20)와 진행 상황
- DB 스키마: [schema.sql](schema.sql) — `tf_` 테이블 7개와 제약

## 3. 고른 해결 방법(공고 3장)

| 기능 | 고른 해결 | 어떻게 | 근거 |
| --- | --- | --- | --- |
| 다른 사람의 변경 보기 | **어려운 해결** | `st.fragment(run_every=3)`로 학생 화면과 관리자 화면의 바뀌는 부분만 3초마다 다시 그림. 어려운 해결이므로 `refresh` 단추는 두지 않음(공고 2.7) | 커밋 `4612515`, `051361f`. 다른 학생의 지원이 3.7초 안에 보이는 것을 브라우저에서 확인 |
| 필수 포함 역할을 지킬 수 없는 팀 | **어려운 해결** | 지원 단계에서 "지원자가 들어간 뒤 남는 자리 < 아직 채우지 못한 필수 포함 역할 수"이면 막음. 기획자·웹 프로그래머를 둘 다 할 수 있는 학생은 하나로만 셈 | 커밋 `cf7326a`, 부록 3 어려움 11단계 |
| 같은 팀에 대기 중인 지원이 여럿 | **어려운 해결** | 모든 팀원이 찬성해 승인하려는 때에 정원·주 역할 중복·필수 포함 역할 자리를 다시 검사. 처리 순서는 투표가 끝난 순서 | 커밋 `b0161c4`, 부록 3 어려움 8단계 |
| 마지막 자리에 두 명이 동시에 들어감 | **어려운 해결** | `tf_members`의 기본 키 `(team_id, slot_no)`, `student_id` 유일, `slot_no between 1 and 4` | [schema.sql](schema.sql), 커밋 `cdea718` |
| AI 응답이 늦을 때 | **어려운 해결** | 요청을 작업 스레드에서 보내고, 모델을 부른 때부터 시계로 재서 120초가 되면 끊고 다음 모델로 | 커밋 `838746d`, [teamform/ai.py](teamform/ai.py)의 `ask_models` |
| 3차 모델까지 실패 | **어려운 해결** | 검사 다섯 가지를 모두 통과하는 배정을 모든 경우를 따져 찾아 두고, 세 모델이 모두 실패하면 그 배정을 씀 | 커밋 `407ea4c`(배정 찾기), `4612515`(연결) |
| AI 대기 중 화면 | **어려운 해결** | `assign_status`에 "2차 모델(…)의 응답을 기다리는 중… 12초 / 120초"와 끝난 시도 기록을 보임 | 커밋 `838746d` |
| DB(Supabase)가 일시정지되지 않게 | **어려운 해결** | GitHub Actions 예약 작업으로 하루 두 번(한국 시각 09:17, 21:17) DB에 작은 질의. 마감 날(11/2)에는 배포한 앱도 직접 사용 | [.github/workflows/keepalive.yml](.github/workflows/keepalive.yml), 커밋 `c89b78b` |

## 4. 쓴 모델 3개

1차 `nvidia/nemotron-3.5-super-vl:free`, 2차 `dots-studio/dots-3-note-preview:free`, 3차 `google/gemma-4-31b-it:free`

모두 오픈라우터 무료 모델을 이름으로 직접 지정했다(라우터 `openrouter/free`는 쓰지 않음). 요청에는 `reasoning: {"effort": "low"}`와 `max_tokens: 16000`을 준다(커밋 `a494c8c`).
처음 순서(10/21)는 1차 gemma, 2차 minimax, 3차 dots였으나, 10/31 시험에서 아래 5항의 실패가 나와 순서를 바꿨다(커밋 `23a126a`).

## 6. 클로드가 잘못된 추론이나 답변을 한 사례

| # | 잘못 | 알아챈 방법 | 근거 |
| --- | --- | --- | --- |
| 6-1 | 공고 2.7절 표의 새로 고침 단추 조건 "3장 「다른 사람의 변경 보기」를 **쉬운 해결로 만든 앱만**"을 "있어도 해가 없다"로 넘겨, 어려운 해결(자동 갱신)을 한 앱에도 `refresh` 단추를 넣었다. 채점 프로그램은 이 단추가 있으면 먼저 누르므로, 자동 갱신이 쉬운 해결로 채점될 수 있었다 | 앱 전체를 공고 원문(PDF)과 한 절씩 대조해 달라고 요청했을 때, 2.7절 표의 조건과 다른 곳으로 드러남 | 넣은 커밋 `4612515` → 뺀 커밋 `051361f` |
| 6-2 | 처음 1차 모델로 공고 예시 모델(`nvidia/nemotron-3-super-120b-a12b:free`)을 시험해 보지 않고 추천했다 | 키를 넣은 뒤 모델마다 시험 호출을 보내 보니 HTTP 404 | 처음 추천을 적은 커밋 `cdea718`(구현 계획 3.3) → 바꾼 커밋 `3cbffe4` |

## 확인 방법

- 연습 시나리오 3개(e-class에서 받은 [data/](data) 명단 그대로)를 채점 프로그램처럼 화면으로 처음부터 끝까지 실행하는 테스트: [tests/test_scenarios_ui.py](tests/test_scenarios_ui.py). 모든 동작의 결과 안내 첫 단어가 부록의 기대 결과와 같고, 확정한 팀 구성이 검사 다섯 가지를 지킨다
- 로컬 실행: `.env`에 `OPENROUTER_API_KEY`, `DATABASE_URL`, `ADMIN_PASSWORD`를 넣고 `streamlit run streamlit_app.py`. 테스트는 `pytest`(DB를 처음 상태로 되돌리므로 채점 기간에는 돌리지 않는다)
